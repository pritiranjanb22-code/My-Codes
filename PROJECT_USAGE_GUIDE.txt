## QUICK START
```bash
# 1. Install
pip install airllm

# 2. Basic inference (any model)
python -c "
from airllm import AutoModel
model = AutoModel.from_pretrained('Qwen/Qwen3-32B')
input_tokens = model.tokenizer(['What is the capital of France?'], return_tensors='pt', truncation=True, max_length=128)
output = model.generate(input_tokens['input_ids'].cuda(), max_new_tokens=20)
print(model.tokenizer.decode(output.sequences[0]))
"
```

## KEY FEATURES & USAGE

### Run Massive Models on Tiny VRAM
| Model | Size | VRAM Required |
|-------|------|---------------|
| Qwen3-32B | 32B | ~2-3 GB |
| Qwen3.8-27B (VL) | 27B | 3.33 GB |
| Qwen3.8-Flash-Next (MoE) | 125B | 5.95 GB |
| Llama 3.1 70B | 70B | ~4 GB |
| Llama 3.1 405B | 405B | ~8 GB |
| DeepSeek-V3 | 671B | ~12 GB |
| Kimi K3 | 2.8T | 3.72 GB |

### Configuration Options
```python
model = AutoModel.from_pretrained(
    "Qwen/Qwen3.8-Flash-Next",
    compression='4bit',           # '4bit' or '8bit' for 3x speedup (needs bitsandbytes)
    profiling_mode=True,          # Show layer load times
    prefetching=True,             # Overlap disk load with compute
    delete_original=True,         # Save disk space after splitting
    layer_shards_saving_path="/custom/path",  # Custom shard location
    hf_token="your_hf_token",     # For gated models
    max_seq_len=512
)
```

## COMMON ISSUES
- **MetadataIncompleteBuffer**: Out of disk space (splitting is disk-heavy)
- **max() arg empty sequence**: Use `AutoModel` not specific class (e.g., AirLLMLlama2)
- **401 Gated model**: Provide `hf_token` parameter
- **Padding token error**: Set `padding=False` in tokenizer call

## CLI USAGE
```bash
# Install globally
npm install --global rea-agents
rea --help

# Analyze JavaScript/Electron app
rea analyze-javascript-application /path/to/app --json

# Native binary analysis (needs Hopper/Ghidra/IDA)
rea analyze-native /path/to/binary

# Update REA
rea update
# Or via npx:
npx rea-agents@latest setup
```

## SUPPORTED ANALYSIS TARGETS
| Target | Requirements | Output |
|--------|--------------|--------|
| Native binaries (ELF/PE/Mach-O) | Hopper, Ghidra, or IDA | Pseudocode, asm, strings, calls |
| Go/Rust binaries | Built-in (no tool needed) | Compiler info, modules, deps |
| JavaScript/Electron | Node.js + npm | Modules, imports, IPC, routes |
| Websites | Chrome-family browser | DOM, scripts, network, screenshots |
| .NET assemblies | None (static) | Metadata, CIL, native deps |
| Android APK | JADX + JDK | Manifest, classes, decompiled methods |
| Android device | adb | Processes, logs, dumps, screen caps |
| WASM/EVM/SQLite/pcap/Signals | Various | Specialized parsing |
| Firmware | Binwalk/Unblob | Extraction + native handoff |
| Flutter/JEB/APKTool | Various | Dart snapshot, JEB projects, resources |

## MCP TOOLS (for agents)
Once setup, your agent can call these tools:
- `analyze_native_binary` - Deep binary analysis
- `analyze_javascript_application` - JS/Electron app inspection
- `analyze_android_apk` - APK decompilation
- `analyze_website` - Browser-based analysis
- `capture_process` - Runtime process observation
- `inspect_wasm_artifact` - WASM validation
- `analyze_dotnet_assembly` - .NET metadata + CIL
- `analyze_evm_bytecode` - Smart contract analysis
- And 15+ more...

## KEY PRINCIPLES
- **Local-only**: No data leaves your machine
- **Read-only**: Never modifies target binaries/apps
- **Evidence-based**: Every finding includes source, confidence, limitations
- **Fail-closed**: No integration until scope/authority verified
- **Ownership semantics**: Proper process lifecycle management

## CONFIGURATION
- Provider selection: `REA_GHIDRA_STARTUP_TIMEOUT_MS`, `REA_HOPPER_STARTUP_TIMEOUT_MS`
- Native analysis engine: Configured during `rea setup` or via `server.json`
- MCP registration: `npx rea-agents setup` (backs up existing config)
